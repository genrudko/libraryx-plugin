# M1 indexed core

M1 establishes the first real LibraryX data path:

KOReader book file
  -> DocumentRegistry support check
  -> FileManagerBookInfo metadata
  -> BookList progress/status
  -> ReadHistory last-open time
  -> normalized LibraryX model
  -> libraryx.sqlite3

Current slice indexes one explicit file at a time. Recursive/chunked scanning and
the AlReaderX navigation UI are subsequent M1/M2 slices.

Important Kindle detail: KOReader reports Device:canUseWAL() == false on Kindle,
so LibraryX uses SQLite TRUNCATE journal mode there.


## Recursive scan slice

The synchronous scan core now:
- recursively walks a selected root;
- ignores files unsupported by KOReader;
- compares size + mtime to skip metadata extraction for unchanged books;
- still refreshes reading progress/status for unchanged books;
- tags every seen book with a monotonically increasing scan token;
- deactivates previously indexed books under the same root that were not seen;
- exposes progress/error/cancel callbacks.

UI-friendly chunking/yielding is intentionally the next slice before this is
wired to a menu action on Kindle.
