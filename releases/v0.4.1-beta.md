# LibraryX 0.4.1 Beta

## Русский

Исправляющий и инфраструктурный релиз после аудита v0.4.0-beta. Основной акцент — корректная работа настроек плотности списка, безопаснее обновление плагина и CI, который больше не может показать PASS при фактически пропущенных Lua-тестах.

### Исправления

- старый диалог «Масштаб списка» переведён на тот же ключ `list_density`, что и Settings v2 и меню `⋮`;
- режим Auto и ручные значения 3–10 теперь используют единый источник настроек;
- удалены устаревшие тестовые ожидания, относившиеся к старой реализации карточек, метаданных и списка серий.

### Безопасность обновления

- ZIP обновления сначала распаковывается в отдельный staging-каталог рядом с установленным LibraryX;
- перед активацией проверяются структура пакета, `_meta.lua`, имя плагина и ожидаемая версия;
- пути архива с `..`, абсолютными путями или обратными слешами отклоняются;
- рабочий каталог заменяется только после успешной распаковки и проверки;
- если активация staging-каталога завершается ошибкой, предыдущая установка восстанавливается из backup;
- удалённые в новой версии файлы больше не остаются в каталоге как хвосты старой установки;
- updater выбирает только релизные файлы `*.koplugin.zip`, а список GitHub Releases запрашивается до 100 записей.

### Проверки и CI

- `tools/check.sh` теперь завершается ошибкой, если Lua/LuaJIT отсутствует, вместо ложного PASS со SKIP;
- каждый Lua-тест запускается отдельным процессом — аргументы больше не могут маскировать непрогнанные тестовые файлы;
- release workflow явно устанавливает LuaJIT перед проверками;
- добавлен runtime-тест updater: успешная полная замена, отказ пакета с неверной версией и rollback при ошибке активации.

## English

Maintenance and reliability release following an audit of v0.4.0-beta. The main focus is consistent list-density settings, safer plugin updates, and CI that can no longer report PASS when Lua tests were actually skipped.

### Fixes

- the legacy “List scale” dialog now uses the same `list_density` setting as Settings v2 and the `⋮` footer menu;
- Auto mode and manual values 3–10 now share one source of truth;
- stale test expectations from older card, metadata and series-list implementations were updated to the current contracts.

### Safer updates

- update ZIPs are extracted into a separate staging directory next to the installed LibraryX;
- package structure, `_meta.lua`, plugin name and expected version are validated before activation;
- archive paths containing `..`, absolute paths or backslashes are rejected;
- the live plugin directory is replaced only after extraction and validation succeed;
- if staged activation fails, the previous installation is restored from backup;
- files removed by a newer release no longer remain as stale leftovers;
- the updater accepts only `*.koplugin.zip` release assets and requests up to 100 GitHub Releases.

### Checks and CI

- `tools/check.sh` now fails when Lua/LuaJIT is unavailable instead of returning a false PASS with skipped tests;
- every Lua test is executed separately, preventing extra filenames from being treated merely as script arguments;
- the release workflow explicitly installs LuaJIT before running checks;
- updater runtime coverage now exercises successful replacement, version-mismatch rejection and rollback after forced activation failure.
