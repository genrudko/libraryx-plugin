# LibraryX 0.4.3 Beta

## Русский

Hotfix для сломанного пакета v0.4.2-beta.

В v0.4.2-beta был добавлен runtime-модуль `libraryxlifecycle.lua`, но старый `tools/package.sh` собирал ZIP по ручному списку файлов и не включил новый модуль. Поэтому ZIP содержал `main.lua` с `require("libraryxlifecycle")`, но не содержал сам файл. KOReader не мог загрузить LibraryX: плагин исчезал, а сохранённый `start_with=libraryx` мог отображаться как `nil`.

### Исправлено

- `libraryxlifecycle.lua` гарантированно входит в ZIP;
- упаковщик больше не использует ручной список Lua-модулей;
- все top-level `*.lua` плагина копируются автоматически;
- packaging fail-closed сравнивает набор Lua-файлов source и staging;
- сохранены исправления v0.4.2-beta: Exit/Restart lifecycle, раздел обновлений и staged updater.

### Обновление с v0.4.2-beta

Из-за ошибки загрузки v0.4.2-beta не может обновить себя встроенным updater. Один раз установите v0.4.3-beta ZIP вручную поверх `libraryx.koplugin`. После этого встроенный updater снова должен работать.

## English

Hotfix for the broken v0.4.2-beta package.

v0.4.2-beta introduced `libraryxlifecycle.lua`, while `tools/package.sh` still assembled ZIPs from a handwritten file list and omitted the new module. The ZIP contained `main.lua` requiring the module but not the module itself, so KOReader could not load LibraryX.

### Fixed

- `libraryxlifecycle.lua` is guaranteed to be packaged;
- all top-level plugin `*.lua` files are copied automatically;
- packaging fails closed if source and staging Lua module sets differ;
- all v0.4.2-beta lifecycle and updater fixes remain included.

### Updating from v0.4.2-beta

Install v0.4.3-beta manually once over `libraryx.koplugin`; after that, the built-in updater should work again.
