# LibraryX 0.4.6 Beta

## Русский

Исправление ReaderUI-кнопки LibraryX после повторной проверки на физическом устройстве.

### Точная причина

В v0.4.4/v0.4.5 LibraryX добавлял `libraryx_reader` в `reader_menu_order["KOMenu:menu_buttons"]`, но не создавал обязательную таблицу порядка:

```lua
libraryx_reader = {}
```

KOReader `MenuSorter` воспринимал такой top-level ID как обычный action и на финальном cleanup удалял его, потому что у него не формировался `sub_item_table`. Поэтому кнопка не могла появиться вообще, независимо от сброса `tab_item_table`.

### Исправлено

- `order.libraryx_reader = {}` теперь создаётся так же, как штатный `filemanager = {}`;
- сохранена инвалидация ReaderMenu cache после поздней регистрации внешнего плагина;
- кнопка остаётся сразу после штатного файлового менеджера;
- callback, icon и `remember=false` сохраняются в итоговом top-level элементе.

### Проверка

Исправление воспроизведено на актуальном upstream `frontend/ui/menusorter.lua` KOReader:
- без `libraryx_reader = {}` кнопка удаляется;
- с `libraryx_reader = {}` кнопка остаётся;
- итоговый элемент сохраняет `id=libraryx_reader`, `icon=book.opened` и callback LibraryX.

---

## English

Fixes the ReaderUI LibraryX button after repeated physical-device validation.

The real issue was structural: LibraryX added `libraryx_reader` to `KOMenu:menu_buttons` but did not define the matching empty order table `libraryx_reader = {}`. KOReader's MenuSorter therefore treated it as a regular action and dropped it during top-level cleanup.

v0.4.6-beta now mirrors KOReader's built-in `filemanager = {}` structure. The fix was reproduced directly against the current upstream MenuSorter implementation.
