# LibraryX 0.4.2 Beta

## Русский

Исправляющий релиз по результатам проверки на физическом Kindle/PW5. Закрывает два пользовательских дефекта v0.4.1-beta: неудобно/неочевидно доступный updater в настройках и LibraryX, который мог оставаться отдельным верхнеуровневым окном после выхода из KOReader.

### Исправлено: выход из KOReader

- добавлен отдельный lifecycle-контур LibraryX для top-level окон, которые живут вне дерева FileManager/ReaderUI;
- LibraryX теперь обрабатывает Exit и Restart и на реальном завершении KOReader закрывает все свои оставшиеся top-level окна;
- сохранено корректное поведение при обычной навигации:
  - FileManager → книга не уничтожает LibraryX;
  - книга, открытая из LibraryX, при обычном закрытии возвращает пользователя в LibraryX;
  - Reader → Reader сохраняет происхождение перехода;
  - окно LibraryX не должно переживать Exit/Restart и удерживать UIManager stack;
- persistent LibraryX views, отдельное окно настроек и окна updater теперь регистрируются в lifecycle tracker.

### Исправлено: обновления в настройках

- раздел «Обновления» поднят на первую страницу настроек — сразу после «Библиотека»;
- основной пункт внутри раздела по-прежнему показывает установленную версию и запускает ручную проверку GitHub Releases;
- native-пункт «Обновления» получил fallback `sorting_hint = "libraryx_tab"`, поэтому старый пользовательский порядок меню KOReader не должен выбрасывать новый пункт из вкладки LibraryX;
- исправлена ошибка updater v0.4.1-beta: ожидаемая версия релиза вычислялась, но в реальном install path в staged validation передавалась необъявленная переменная; теперь ZIP обязательно сверяется с выбранной версией перед активацией.

### Проверки

- добавлены runtime-тесты lifecycle: дедупликация/закрытие top-level окон, one-shot возврат из Reader, Exit backstop;
- добавлены статические integration-gates на Exit/Restart wiring, reader provenance и отслеживание окон;
- тесты требуют, чтобы «Обновления» находились на первой странице Settings между «Библиотека» и «Список книг»;
- updater wiring-тест не позволяет снова потерять передачу ожидаемой версии в staged install.

## English

Maintenance release based on testing on a physical Kindle/PW5. It fixes two user-visible regressions in v0.4.1-beta: update controls that were not discoverable enough in Settings, and LibraryX remaining as a separate top-level UI layer after exiting KOReader.

### Fixed: KOReader exit lifecycle

- added a dedicated LibraryX lifecycle layer for top-level widgets that live outside the FileManager/ReaderUI widget tree;
- LibraryX now handles Exit and Restart and drains its remaining top-level widgets during a real KOReader shutdown;
- normal navigation remains distinct from application exit:
  - FileManager → Reader keeps LibraryX parked;
  - a book launched from LibraryX returns to LibraryX when normally closed;
  - Reader → Reader transitions preserve launch provenance;
  - LibraryX must not survive Exit/Restart and keep the UIManager stack alive;
- persistent LibraryX views, standalone Settings and updater dialogs are lifecycle-tracked.

### Fixed: updates in Settings

- the Updates section is now on the first Settings page, immediately after Library;
- its primary action still shows the installed version and performs a manual GitHub Releases check;
- the native Updates item now has a `sorting_hint = "libraryx_tab"` fallback so stale/custom KOReader menu ordering cannot orphan it outside the LibraryX tab;
- fixed an updater v0.4.1-beta wiring bug: the selected release version was not actually passed into staged package validation because the install path referenced an undefined variable; the downloaded ZIP is now validated against the selected release version before activation.

### Verification

- added lifecycle runtime tests for widget draining, deduplication, one-shot Reader return provenance and Exit backstop;
- added static integration gates for Exit/Restart wiring, Reader provenance and lifecycle tracking;
- Settings tests require Updates to stay on the first page between Library and Book list;
- updater wiring tests prevent the expected-version validation argument from being dropped again.
